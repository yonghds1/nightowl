# Nightowl Verify — 独立机器门禁验证与仲裁技能

本技能负责在实现代码交付后、合并至主分支前，执行严格的独立机器验证。

触发时机：任务实现完成待合并、重试排错、或代码审查前进行客观事实核验。

## 核心职责与执行契约

1. **自动寻址与执行**：
   运行标准命令：
   ```bash
   nightowl verify --id <id>
   ```
   CLI 会自动定位至 `worktrees/<id>` 隔离工作区中执行该任务预设的全部验收命令。如需手动指定执行目录，可使用 `--cwd <dir>` 选项。

2. **严格判定原则**：
   - 机器验证严格以命令退出码为唯一准绳（`exit code === 0` 即为通过，非 0 即为失败）；
   - 不进行任何不可靠的文本正则猜测，杜绝把 `tsc --noEmit`、`eslint` 等无计数命令误判为失败。

3. **失败落盘结构化反馈 (`feedback.json`)**：
   若门禁命令失败，系统自动提炼纯净错误摘要，并原子写入：
   ```
   .nightowl/tasks/<id>/feedback.json
   ```
   实现代理应直接读取该文件中的 `command`、`exitCode` 与 `diagnostic` 关键段落进行针对性排错，禁止盲目反复重试。

4. **成功回执与防偷改强绑定**：
   所有门禁命令全部通过后，CLI 会在任务状态中记录：
   - `head`：当前工作区的精确 `git rev-parse HEAD` 哈希；
   - `dirty_diff_hash`：工作区状态指纹。
   
   在执行 `nightowl worktree merge <id>` 时，底层会自动校验当前代码版本是否与验证回执一致。若在验证通过后又改动了代码，合并将被直接阻断并要求重新运行 `verify`。
