# Nightowl Report — 晨会发版决策报告

run 阶段调度结束（全部任务做完或全部阻塞）后，主代理直接运行命令生成决策报告并落盘：

```bash
nightowl report
```

报告将落盘至 `.nightowl/nightowl.report.md`，并在用户回到会话时主动当面汇报。

## 报告核心结构

1. **🚦 10 秒发版决策看板 (Executive Summary)**：
   - **发版判定**：`🟢 【可发版】` / `🟡 【条件发版】` / `🔴 【不可发版】`，附一句话决策原因；
   - **进度一览**：已完成任务数、P0 任务完成率、当前阻塞任务数；
   - **工时偏差**：预估总工时 vs 实际总耗时，计算偏差百分比；
   - **返工警报**：代码审查打回重试轮次与待优化建议 (Nits)。

2. **任务与审查总览**：
   - 任务清单明细（ID、负责人、优先级、预估/实际耗时、最终状态）；
   - 阻塞任务清单及具体阻断原因；
   - 审查过程与历史轮次记录。

3. **Git 聚合变更**：
   - 当前目录是 Git 仓库时，按任务 ID `[#<id>]` 分组聚合该仓提交，过滤无关 merge；非 Git 根不会自动聚合子仓，需要逐仓核实后补充汇报。

## 向用户汇报模板

用户回到对话后，主动提炼决策看板核心三行进行精炼汇报。以下是单仓库的示例，必须替换为实际证据；混合模式使用逐仓提交状态，不照搬“已合并”：

```text
报告已生成：
- 发版判定：🟢 【可发版】（全部 P0 任务已通过机器门禁与代码审查）
- 昨晚进展：完成 T1、T2 两个核心任务；总耗时 65m（预估 60m，偏差 +8%）；无阻塞任务。
- 代码合入：已合并分支 nightowl/T1、nightowl/T2，共 4 个原子提交。
详细报告见 .nightowl/nightowl.report.md。
```

## 混合工作区报告

原目录执行不具有 worktree 隔离和跨仓版本绑定。分别核实相关子仓提交/推送状态并在汇报中说明；`WORKTREE_MERGE_SKIPPED:` 不表示子仓已合并，`PUSH_SKIPPED_NO_GIT` 不表示已推送任何子仓。不能用完成任务数替代提交或推送证据。
